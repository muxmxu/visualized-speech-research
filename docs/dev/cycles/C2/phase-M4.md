## Internal recording protocol shared by T1 and T2

The §7 reference to §11 covers the arm and Calibrate controls. Use authenticated `POST /api/record/arm` and `POST /api/record/calibrate` for their commands and the existing server-to-browser `/ws` for feedback. This keeps control alongside §11's existing HTTP commands and uses §6 event types, without extending browser-to-server WS, adding product settings or changing the public Python API. Decision D52 records this binding and the conventions below. T3 appends it to DESIGN §21.

| Exchange | Body or event |
| --- | --- |
| `GET /audio/devices` | `{hostname, devices: [{id, name, max_input_channels, max_output_channels, default_samplerate}], default_input: number or null, default_output: number or null, reason: string or null}`. Device IDs are PortAudio indices. Missing sounddevice yields an empty list with a reason. |
| `POST /record/arm` | `{input_device, sr, blocksize, mapping}`. A mapping entry is `{lane: string or null, channels: number[]}`. Lane ID targets an existing audio lane with one channel or two consecutive channels. Each null entry targets a new mono lane from one selected input channel. Indices are zero-based on the wire and one-based in the UI. An empty mapping disarms the input meter. |
| `POST /record/start` | `{input_device, output_device?, sr, blocksize, subtype, mapping, overdub, latency_ms, start_time}`. Fields other than `output_device` are sent on every request. Input device may be null for the server default. Omit output for non-overdub. An absent output device in overdub uses the server default. `sr` and `blocksize` are integer controls, subtype is `FLOAT`, `PCM_24` or `PCM_16`, null `latency_ms` selects the measured stream latency sum, and `start_time` is the current session playhead in seconds. An empty mapping is the default device's first-channel new mono recording. The start response is the current record-state object. |
| `POST /record/stop` | No body. Return `{lanes: AudioLaneMetadata[]}` after draining, closing and publishing audio. Each affected audio lane exposes `record_warnings: [{time_s, type}]`, with recording-relative seconds and `input_overflow` or `output_underflow`. Existing audio lanes have an empty array. Broadcast `lanes_changed` and the resulting record state. |
| `POST /record/calibrate` | `{input_device, output_device, sr, blocksize}`. The Record panel tells the user to connect output 1 to input 1. A brief click and the measured lag yield `{latency_ms}`, which populates the editable compensation field. Capture uses the selected device pair and leaves no session lane or recording file. |
| `POST /mixdown` | `{t0, t1, sr, path, subtype}` using half-open session seconds and explicit output path. Return `{path, clipping: boolean}` and notify when clipping is true. Use the existing WAV/FLAC writer and format-compatible subtype choices. |
| WS `record_state` | JSON `{type: "record_state", state: "idle" or "armed" or "recording", mapping, start_time: number or null, notice: null or "microphone_permission" or "device_clock_drift"}`. Arm responds with this object and sends it on WS. A new connection receives current state when armed or recording. Idle is implicit before the first event so existing idle clients receive the same stream. Notices are events from the current take. Use existing `error` event for device failure with the standard error fields. |
| WS `record_meter` | JSON `{type: "record_meter", channels: [{peak_dbfs, rms_dbfs, clip}]}` at about 30 Hz, in channel order. JSON null dB values denote exact silence and render as −∞. |
| WS `record_preview` | Use the shared §6 frame codec with f32 `[C, 2, W]`, minima then maxima per channel. Header includes `type: "record_preview"`, mapping ordinal `target`, `sr`, `first_sample`, `samples_per_column`, and `sample_count` measured in recording samples. Each column covers one block, last column may be short. Browser positions it using the start time and recording sample rate. Send roughly every 100 ms. |

For shared mixing, preserve channel order, duplicate mono onto stereo when mixed together and use the existing playback audibility rule. Larger layouts in file mixdown preserve their channel order and match the widest audible lane; unmatched channels are silent. For overdub, use up to two channels supported by the selected output and derive its mono or first two output channels from the same mixed audio. Use `resample_poly` when rates differ and round lane offsets on the target sample grid. A recording keeps the §11 filename pattern, adding a suffix only when needed to keep recorded files distinct and sanitizing the display name to a filename component. These defaults let the §11 controls work without another setting.
