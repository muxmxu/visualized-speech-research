## Shared scan protocol and conventions

| Exchange | Wire |
| --- | --- |
| `POST /api/datasets` | JSON `{sources:string[], bandwidth_drop_db?:number, analyzers?:[{id,params}]}` → `{id}`. Each path names a server directory or CSV, TSV or JSONL manifest. Use §13's 50 dB threshold by default. Scalar controls use the M5 parameter schemas and send each selected audio analyzer's ID and typed parameters. |
| `GET /api/analyzers` | Preserve the M5 response and add descriptor field `output` with value `"scalars"`, `"other"`, or null from the return annotation. Null denotes an undeclared output. |
| WS `job_progress` | JSON `{type:"job_progress",id,status,completed,total,error}`; status is `running,done,cancelled,failed`, counts are files and error is the §7 error object or null. Progress and completion update one dataset job on the existing authenticated socket. Track events by ID even before the POST reply arrives. Retain finished rows on cancellation. |
| `GET /api/datasets/{id}/rows` | Column JSON `{columns:string[],data:{[column]:cell[]}}`, with ordered names and equally sized vectors. Rows follow input source order and deterministic within-source enumeration; each zero-based array index is its stable row index at completion. Cells are the native JSON values or null when unavailable. Missing manifest cells and unavailable metrics are null; file failures include `error`. The `ltas` vector stays server-side. |
| `POST /api/datasets/{id}/ltas` | `{groups:{[label]:number[]}}`, containing only AG Grid filtered row indices. The frame header is `{groups:string[],unit:"db_per_hz"}`, with named f32 arrays `freqs:[F]`, `mean:[G,F]`, `p10:[G,F]`, `p90:[G,F]`. Use one common grid `20 * 2**(k/24) ≤ 24000` and retain NaNs in the frame. Browser requests at most 16 groups per batch and plots the full filtered selection. |
| `POST /api/datasets/{id}/cancel` | No body, respond `{id}` after requesting cancellation. Stop submitting new files and publish the final completed rows when current work has stopped. |

Use resolved source paths as stable `source` labels and absolute file `path` in rows. A directory is recursive and matches §13 extensions. A manifest keeps its row order and supplied metadata, resolves relative paths beside itself and uses `meta.<name>` only where a header collides with generated columns. Name Scalar columns `<analyzer-id>.<result-key>`. Use genuine audio-Scalar results through the M5 registry. An annotated Scalar is directly eligible, and an audio plugin without a declared output can be selected explicitly as a Scalar. Report a per-row analyzer error through `error` and retain built-in columns when the plugin fails or returns a different output type. Browser export and CLI write the same column order and values, with null as an empty cell. Record these §13 bindings in DESIGN §21 D54 through T3.
