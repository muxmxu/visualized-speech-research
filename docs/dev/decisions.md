## 2026-11-17（M0 计划复核后的修订）

- **D35 按现行交付授权修订 C1 周期计划，M0 计划绑定独立 recon。** M0 的首次 Plan Review 结论为 FAIL，指出 R1.7 的旧禁止 push 语句与 H34–H36、LIFECYCLE 的 Push 规则相冲突，且初稿缺少独立 recon 输入。Overall Planner 只作一次 Amendment A1：R1.7 改为按已有授权 push 与条件性创建 GitHub Release；recon 的事实写入 M0 phase plan，未验证的环境与执行通道保留为派发阻塞。依据：`cycles/C1/reports/plan-review-M0.md` 与 `recon-M0.md`。此决定不改变产品范围，也不增添新的发布授权。回退：如既有授权变化，按新的 Human 输入重新修订交付标准。
- **D36 framed binary 的补齐和多数组偏移约定。** `docs/DESIGN.md` §6 的 8 字节边界从整条消息的首字节起算，因此 payload 起点是 `4 + header_len` 向上补齐到 8 的倍数；多数组的 `offset` 从 payload 首字节起算，各数组起点按 8 字节对齐。依据：§6 的消息布局及「payload 依次拼接」；该约定让 Python 与 TypeScript 的往返可逐字节核对。涉及产品；由 M0 integration task 追加至 DESIGN §21。回退：经 Scope gate 修改 §6 并同步两个 codec。
- **D37 设备 self-check 的相对误差约定。** 对 DESIGN §4 指定的 stft、istft、rfft、matmul 分别在候选设备和 CPU 上用相同的非零合成输入计算，误差为 `||candidate-reference||₂ / ||reference||₂`，每项严格小于 `1e-4` 才通过。依据：§4 的四项算子与相对误差阈值；分母选非零参考避免无定义比值。涉及产品；由 M0 integration task 追加至 DESIGN §21。回退：经 Scope gate 修改 §4 并同步 self-check 与测试。
- **D38 M0 的 Git 事务使用独立顶层 Worker 会话。** 已验证独立进程能启动与当前 Controller 分离的顶层执行主会话；按 consultant 结论，T1–T5 的任务 diff 经独立审核后，由该会话执行 `impl check`、精确 stage 和 task 分支 commit。T6 由同类顶层 integration Worker 独占最终树，按 LIFECYCLE 执行 merge、检查与 squash；Controller 不合并，collaboration subagent 不 stage、commit 或 push。依据：H41 已授权 Git 操作、M0 计划的执行通道阻塞、`impl` 与 LIFECYCLE 的角色边界。当前只读调用已验证，写入事务须以首次实际结果为证据。回退：顶层通道不可用时停止依赖分支与 T6 派发，另作执行通道决定。
- **D39 按 H43 修正两处开发配置冲突。** Astra 核对后决定：源配置与实际 ESLint 配置同步改写一条说明注释，避免规则脚本对注释中的禁用词产生 C5 误报，不改任何可执行规则；Ruff formatter 只排除 `docs/DESIGN.md` 与配套 skill 的 Markdown 文件，其他格式检查不变。依据：`cycles/C1/reports/M0-T1-audit-1.md`、H43 和 Astra 的独立核对。回退：若规则检查器将来能识别注释，可删除精确排除或恢复说明文字，经当时规则流程核对。

- **D41 T1 的测试发现范围与 torch 来源按平台限定。** Vitest 仅发现 `frontend/tests/**/*.test.{ts,tsx}`，Playwright 仅发现 `frontend/tests/e2e/`，保留已批准的 only 禁用与零重试设置。现有 torch CPU 索引只匹配 Linux aarch64；x86 Linux 与 macOS 使用 PyPI，不强制 CUDA 主机装 CPU wheel。依据：`cycles/C1/reports/M0-T1-review-1.md` 的两项缺陷及独立 consultant 对 uv source marker 的核对；这是 T1 基础配置的修复，不新增运行时依赖或应用选项。回退：若某平台的实际 wheel 选择不符合 DESIGN §4，依据该平台安装证据修正 source marker 与锁文件，保留设备自检行为。
- **D42 Continue the authorized unattended run after the M0 invocation estimate is exceeded.** H42, H44, H46, and H50 direct uninterrupted progress through completion and explicitly authorize use after a usage reset; the phase estimate is not a paid-compute cap, and this decision adds no external spending or product scope. The Controller records actual invocations in the private state and keeps the existing acceptance and review requirements. Reversal: a later explicit Human stop or budget limit.
- **D43 Clarify masked PCM chunk bounds and selection bounds on the existing route.** The same 20-second chunk can lie at a selection edge or inside a longer selection, so the existing `t0` and `t1` chunk query alone cannot determine the specified mask transition; optional `selection_t0` and `selection_t1` identify the enclosing T-F selection while the existing chunk bounds, route, unmasked behavior, and 20-second request limit remain intact. H42, H44, and H46 authorize the necessary technical correction without a questionnaire, and the independent M1 Plan Review documented the contradiction. The architecture task records the exact query and validation contract in DESIGN §§7 and 9.4 and appends this decision to §21 before implementation. Reversal: a later approved interface design replaces these fields while preserving the selection-edge and chunk-continuity acceptance.
- **D44 Reject full-spectrum intervals longer than the specified FFT cap.** DESIGN §8.4 requires a transform length at least as long as the selected sample interval and caps that length at 2^24, so an interval exceeding 2^24 samples has no valid transform under the current specification; the public DSP entry raises a value error and the HTTP boundary returns a visible client error instead of silently discarding samples. H42, H44, and H46 authorize this technical clarification, and M1-T1 semantic review reproduced lost tail data on the old code. The M1 integration task appends this decision to DESIGN §21. Reversal: a later approved spectral method may define a full-interval result above the cap without losing input contributions.
- **D45 Define the §15 mask edge profile and reject unusable inverse windows at the HTTP boundary.** Each time and frequency axis keeps unit gain inside the inclusive selection, uses an exterior half-cosine over two frame or bin steps, and reaches zero beyond that width; the two weights multiply at corners and follow the original selection edges across playback chunks. A positive Gaussian parameter can yield an effective float32 window that violates the inverse's NOLA condition, so the authenticated PCM boundary reports that parameter as invalid instead of returning a broken audition. H42, H44, and H46 authorize this necessary numerical choice, and the M1-T3 task plan contains the independent oracle and regression fixtures. The M1 integration task appends this decision to DESIGN §21. Reversal: a later approved mask profile can replace the edge weights and their numeric fixture while retaining selection and chunk continuity.
- **D46 Use the reference defaults for omitted mel parameters.** When DESIGN §§8.3 and 16 leave mel parameters unspecified, use 128 bands, 0 Hz to Nyquist and Slaney spacing as in the reference implementation, while retaining the specified calibrated power and Slaney normalization. Explicit mel parameters continue to control the result. The M2 integration task appends this decision to DESIGN §21.
- **D47 Preserve raw feature values in framed f32.** Use DESIGN §6's f32 payload for the §8.5 raw scale so a finite value is not rounded out of range or serialized as a non-JSON maximum. The five dB-like scales retain f16, with invalid conversions rejected at the file or HTTP boundary before lane publication. M2-T5 consumes the framed dtype and M2 integration appends this decision to DESIGN §21.
- **D48 Specify static plot and installer defaults within existing interfaces.** A single supplied spectrogram axes renders and labels the first channel, while comparison renders each channel explicitly and preserves shared ranges. Difference follows argument order and uses a symmetric 1 dB extent when all differences are zero. Skill installation requires at least one explicit agent destination and checks all requested destinations for conflicts before creating a link. M2 integration appends these decisions to DESIGN §21.
- **D49 Bind CLI Tensor launches to one authenticated browser claim.** Preserve the existing `vsr [paths...]` behavior and public routes and replies by defining a private stage and claim on the existing open operation for the CLI and browser. Keep paths in bounded server memory and send only the one-time correlation identifier in the launch fragment, which the browser clears before claiming. The independently reviewed architecture phase records the exact §7 contract and appends this decision to §21 before T5a, including direct loopback for local runtime requests and at-most-once claim behavior.
